本站的前一版是 Hexo 7.3.0，现在跑在 Hugo 0.169 上。两者都是静态站点生成器，最终产物也相同——一堆 HTML、CSS 和 JavaScript，丢给 Nginx 或任意静态托管就能访问。差别不在结果，而在实现路径和日常使用的手感。

这篇把迁移前后的观察整理一下，给同样在做选型的人一个参考。

## 一、架构：运行时依赖与单二进制

这是两者最根本的分歧。

Hexo 是一个 Node.js 应用。渲染 Markdown 靠 `hexo-renderer-marked`，生成页面靠 `hexo-generator-index` 之类的插件，部署靠 `hexo-deployer-*`。这套设计让能力可以无限扩展，代价是项目必须带着一棵 `node_modules`，并且要维护依赖版本。

Hugo 是一个用 Go 编译出的单文件程序。模板引擎、Markdown 渲染、图片处理、多语言、分类系统都是内建的，运行时不需要任何外部依赖。

| | Hexo | Hugo |
| --- | --- | --- |
| 运行环境 | Node.js | 无（单个可执行文件） |
| 扩展方式 | npm 插件 | 内建功能 + 模板 |
| 依赖管理 | `package.json` / `node_modules` | 无 |
| 安装耗时 | 装依赖通常数十秒到数分钟 | 下载解压，秒级 |

这个差异在本地开发时不算明显，但在 CI 里会被放大：Hexo 每次构建都要 `npm install`，Hugo 只需要一个二进制文件。

## 二、构建速度

Hugo 的速度来自并发渲染和编译型语言。本站目前二十来个页面，全量构建耗时约 **0.06 秒**——快到不太像在“构建”，更像是保存文件。

Hexo 在相同页面量级下通常是数秒，具体取决于插件数量：每多一个生成器、一个渲染器，就多一层遍历。这个数字在小站上无感，但文章数到几百上千之后，差距会从“几秒”拉大到“几十秒对不到一秒”，热更新时的体感差异尤其明显。

需要说明的是，这不是“Hexo 慢”的评价，而是两种技术路线的必然结果。如果你的站点只有几十篇，两者都足够快。

## 三、主题与生态

Hexo 的优势在中文本土化。NexT、Butterfly、Fluid 这些主题在国内用户里积累了大量文档和二次开发案例，遇到问题容易搜到答案；插件市场也覆盖了访问统计、文章加密、字数统计这类具体需求。

Hugo 的主题数量更多，但质量分布不均。本站用的「极简 jijian」基于 PaperMod 二次开发，属于中文优化做得比较细的一类；而更常见的通用主题，往往需要自己补一些中文排版细节。

两者的取舍是：**Hexo 更接近“装好就能用”，Hugo 更接近“给你零件自己装”**。前者省时间，后者上限高，前提是你愿意读模板文档。

## 四、内容组织

写作层面的差异比想象中大。

Hexo 的约定是 `source/_posts/` 放 Markdown，开启 `post_asset_folder` 后，同名的资源目录会自动关联，图片路径写相对文件名即可。

Hugo 用 **Page Bundle**：把一篇文章做成一个目录，正文是 `index.md`，图片、附件放在同级目录里。这样资源和正文绑定在一起，迁移和引用都更干净。

Front Matter 都是 YAML，但字段名不同，迁移时要逐一对照：

```yaml
# Hexo
title: 标题
date: 2026-11-12
categories:
  - 技术
tags:
  - Hugo

# Hugo
title: 标题
date: 2026-11-12
categories: ["技术"]
tags: ["Hugo"]
```

此外 Hugo 的 shortcode 机制比 Hexo 的 tag 插件更灵活，可以带参数、嵌套调用，适合做提示框、图注、媒体嵌入这类结构化内容。代价是要学一点 Go template 语法。

## 五、部署与运维

两者的产物都是 `public/`，部署方式没有本质区别：推仓库、走 CI、同步到服务器或对象存储。

区别在构建环节的复杂度。Hexo 的 CI 需要 Node 环境、`npm install`、缓存依赖；Hugo 只需要下载二进制——这也是为什么大多数 CI 模板里 Hugo 的配置往往只有三四行。

本站目前的流程是：`git push` 触发 Actions，构建 Hugo 站点、生成 Pagefind 搜索索引、用 `rsync` 同步到自己的服务器，全程约三十秒。

## 六、迁移成本

从 Hexo 换到 Hugo 不是改个配置就能完成的事，实际要处理的有：

- **Front Matter 字段**：分类、标签的写法，以及自定义字段的映射
- **图片路径**：`post_asset_folder` 的引用方式要改成 Page Bundle
- **固定链接**：`permalink` 规则不同，老文章的外部链接可能失效，需要配置 `aliases` 或重定向
- **主题功能**：评论、统计、目录这些原由插件承担的部分，要换成 Hugo 的内建配置或模板实现

所以迁移前建议把旧站以分支或独立目录的形式保留一段时间，确认新站没有问题再下线路由。本站就把旧站留在了 `legacy-hexo` 分支。

## 七、怎么选

| 你的情况 | 建议 |
| --- | --- |
| 只写文章，希望装好就能用 | Hexo |
| 文章量大，或对构建速度敏感 | Hugo |
| 依赖某个 Hexo 专属插件或主题 | Hexo |
| 不想维护 Node 依赖，部署环境越简单越好 | Hugo |
| 愿意读模板、想深度定制样式和结构 | Hugo |
| 团队更熟 JavaScript | Hexo |

一句话概括：突然来兴趣了，所以就用hugo了。
